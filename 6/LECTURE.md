## Введение в массивы и их важность

### Почему массивы так важны

Массивы важны не потому, что они удобная структура данных (хотя это тоже так), а потому что они отражают то, как
устроена физическая память компьютера. Оперативная память — это большой массив байтов. Каждый байт имеет свой адрес (
число от 0 до максимума). Процессор умеет читать память по адресу — подаёшь адрес, получаешь байт (или 4, или 8).
Понимание массивов = понимание того, как компьютер работает с данными на низком уровне.

### Память с точки зрения процессора

Для процессора память — это линейное адресное пространство. Он ничего не знает о типах данных, объектах или строках.
Процессор просто читает байты по указанным адресам. Что именно лежит в этих байтах — число, буква, часть изображения или
указатель на другую область памяти — определяет программа (компилятор или интерпретатор).

### Кто определяет, где в памяти хранятся данные?

Это зависит от языка:

- **В компилируемых языках (C, C++, Rust)**: компилятор решает, выделить память на стеке (быстро, автоматически) или в
  куче (медленнее, вручную). Он также решает, как выравнивать данные для оптимального доступа процессора.

- **В интерпретируемых и JIT-компилируемых языках (JavaScript, Python, Java, C#)**: за это отвечает виртуальная машина.
  Она управляет памятью, собирает мусор, решает, где и как размещать объекты.

### Высокоуровневые языки и встроенные типы

В высокоуровневых языках программист обычно не думает о том, где и как хранятся встроенные типы (числа, строки,
объекты). Это удобно, но иногда нужно понимать, что происходит "под капотом" для написания эффективного кода. Например,
знание о том, как работают массивы, помогает понять, почему одни операции быстрые, а другие медленные.

## Определение массива

Массив — это структура данных со следующими свойствами:

- **Непрерывная область памяти** — все элементы хранятся друг за другом, без промежутков.
- **Фиксированный размер** — после создания массива его размер нельзя изменить.
- **Элементы одинакового размера** — каждый элемент занимает одно и то же количество байт.
- **Константный доступ по индексу O(1)** — время доступа к любому элементу не зависит от его позиции.

## Производительность и кэш

### Обход массива

Последовательный обход массива (чтение всех элементов по порядку) — это операция O(n), потому что мы касаемся каждого
элемента. Но благодаря устройству процессора последовательный обход работает значительно быстрее, чем случайный доступ к
элементам.

### Массивы и кэш-память

Современные процессоры имеют кэш-память — небольшую, но очень быструю область памяти, которая хранит копии часто
используемых данных. Когда процессор читает один элемент массива, он загружает в кэш не только этот элемент, а целую *
*кэш-линию** (обычно 64 байта) с соседними элементами.

Это даёт огромный выигрыш: при последовательном обходе следующему элементу, скорее всего, уже лежать в кэше, и процессор
не будет ждать медленной оперативной памяти.

```javascript
// Быстро — последовательный доступ (хорошо использует кэш)
const arr = new Array(1000000);
for (let i = 0; i < arr.length; i++) {
    arr[i] = i;
}

let sum = 0;
for (let i = 0; i < arr.length; i++) {  // Последовательно
    sum += arr[i];  // Элементы подгружаются в кэш пачками
}

// Медленно — случайный доступ (плохо использует кэш)
let sum2 = 0;
for (let i = 0; i < arr.length; i++) {
    const randomIndex = Math.floor(Math.random() * arr.length);
    sum2 += arr[randomIndex];  // Каждый раз новый адрес в памяти
}
```

### Сортировка массива

Сортировка — это изменение порядка элементов по определённому правилу (числовому, лексикографическому и т.д.). Разные
языки используют разные алгоритмы сортировки "под капотом". В JavaScript движок V8 использует комбинацию TimSort (для
больших массивов) и Insertion Sort (для маленьких). Сложность встроенной сортировки в среднем O(n log n).

```javascript
const numbers = [5, 2, 9, 1, 5, 6];
numbers.sort((a, b) => a - b);  // [1, 2, 5, 5, 6, 9] — O(n log n)
```

## Безопасность и границы массивов

### Выход за пределы массива

Классическая ошибка низкоуровневого программирования — обращение к элементу массива по индексу, который выходит за его
пределы.

Что произойдёт, зависит от языка:

**В опасных языках (C, C++)** — **Undefined Behavior (UB)**. Спецификация языка ничего не говорит о том, что должно
произойти. Реальная программа может:

- Прочитать мусорные данные (то, что лежит в памяти сразу за массивом)
- Упасть с segmentation fault (если доступ за пределы выделенной памяти)
- Продолжать работать с повреждёнными данными (самый опасный случай, потому что ошибку сложно найти)
- "Безопасно" отработать (ещё опаснее — ошибка скрыта и проявится позже)

```c
// Пример на C — Undefined Behavior
int arr[5] = {1, 2, 3, 4, 5};
int x = arr[10];  // Читаем за пределами массива — UB
arr[10] = 42;     // Пишем за пределами — UB
// Программа может упасть, а может продолжить работу с повреждёнными данными
```

**В безопасных языках (JavaScript, Python, Java, C#)** — программа проверяет границы при каждом доступе. Если индекс
выходит за пределы, выбрасывается исключение.

```javascript
// JavaScript — безопасный язык
const arr = [1, 2, 3, 4, 5];
try {
    console.log(arr[10]);  // undefined — не выбрасывает ошибку
    arr[10] = 42;          // Массив расширяется, дырки до 9 индекса
} catch (e) {
// Ошибки не будет
}

// Но попытка прочитать из отрицательного индекса выбросит ошибку
try {
    arr[-1] = 42;  // TypeError
} catch (e) {
    console.log('Ошибка доступа по отрицательному индексу');
}
```

### Чтение неинициализированной памяти

Ещё один источник UB в опасных языках — чтение памяти, в которую ещё не записывали значения. Язык не гарантирует, что
там лежит ноль, — там может быть любой мусор (остатки от предыдущих вычислений). В безопасных языках память всегда
инициализируется (например, нулями или специальным значением undefined).

```c
// C — чтение неинициализированной памяти
int arr[5];  // Не инициализированы
int x = arr[0];  // Читаем мусор — UB
```

```javascript
// JavaScript — память инициализируется
const arr = new Array(5);  // [empty × 5] — дырки
console.log(arr[0]);        // undefined (безопасно, но не мусор)
```

### Как достигается безопасность на уровне языка?

Безопасные языки добавляют проверки границ при каждом доступе к массиву. Это замедляет выполнение, но делает программу
защищённой от целого класса ошибок. Оптимизаторы и JIT-компиляторы стараются убирать лишние проверки там, где могут
доказать безопасность (например, в цикле, где индекс гарантированно не выходит за пределы).

## Ограничения классических массивов

У массивов есть фундаментальные ограничения:

1. **Фиксированный размер.** Нельзя расширить массив после его создания. Если нужно добавить ещё один элемент,
   приходится выделять новый массив большего размера и копировать все старые данные.

2. **Вставка и удаление в середине — O(n).** Чтобы вставить элемент в середину массива, нужно сдвинуть все элементы
   справа на одну позицию. Аналогично — удаление требует сдвига всех элементов слева.

3. **Вставка и удаление в начало — O(n).** При вставке в начало сдвигается весь массив. При удалении первого элемента —
   тоже весь.

    ```javascript
    // Вставка в середину — все элементы правее сдвигаются
    const arr = [1, 2, 3, 4, 5];
    arr.splice(2, 0, 99);  // [1, 2, 99, 3, 4, 5] — сдвиг элементов 3,4,5
    // Сложность O(n)
    
    // Удаление из начала — сдвиг всех элементов влево
    const first = arr.shift();  // [2, 99, 3, 4, 5] — сдвиг всего массива
    // Сложность O(n)
    ```

## Массивы в JavaScript

### Что такое массив в JS?

Массивы в JavaScript — это не просто массивы в классическом понимании. Это гибридные структуры, которые могут вести себя
по-разному:

- **Обычные плотные массивы** — классический массив, все элементы на своих местах, нет дырок.
- **Разреженные массивы (sparse arrays)** — массивы, в которых есть "дырки" (пропущенные индексы). В JS массив
  становится разреженным, если присвоить значение по индексу, который значительно больше длины.
- **Ассоциативные массивы** — массивы, в которые можно записывать значения по строковым ключам (хотя так делать не
  рекомендуется).

```javascript
// Разреженный массив (с дырками)
const sparse = [];
sparse[100] = 42;
console.log(sparse.length);     // 101
console.log(sparse[50]);        // undefined (дырка)
console.log(0 in sparse);       // false — ключа 0 нет

// Ассоциативное использование (плохая практика)
const bad = [1, 2, 3];
bad["key"] = "value"; 
console.log(bad.length); // 3 (строковый ключ не влияет на длину)
```

### Изменение размера массива в JS

В JavaScript массив может менять свой размер динамически. При добавлении элемента методом `push()` движок либо
использует свободное место в конце (если оно зарезервировано), либо выделяет новый больший буфер и копирует туда все
элементы. Стратегия роста обычно заключается в увеличении ёмкости в 1.5-2 раза.

```javascript
const arr = [];
arr.push(1);   // Ёмкость: 4 (запас)
arr.push(2);
arr.push(3);
arr.push(4);   // Ёмкость: 4 (заполнена)
arr.push(5);   // Расширение: новая ёмкость ~8, копирование всех элементов
```

### Типизированные массивы

Типизированные массивы (`Uint8Array`, `Int32Array`, `Float64Array` и др.) — это настоящие массивы фиксированного размера
с элементами одного типа. Они работают быстрее обычных массивов и позволяют напрямую работать с бинарными данными.

```javascript
// Обычный массив — может хранить что угодно
const regularArray = [1, "hello", {x: 1}, true];

// Типизированный массив — только 32-битные целые числа
const typedArray = new Int32Array(100);
typedArray[0] = 42;
// typedArray[1] = "hello"; — TypeError!

// Преимущество: компактность и скорость
const numbers = new Float64Array(1000000);
for (let i = 0; i < numbers.length; i++) {
    numbers[i] = Math.random();  // Быстрее, чем в обычном массиве
}
```

Преимущества типизированных массивов:

- **Компактность** — числа занимают ровно столько байт, сколько нужно (4 или 8).
- **Скорость** — доступ к элементам быстрее, особенно для численных расчётов.
- **Предсказуемость** — нет проверок типов для каждого элемента.

### Внутренняя иерархия типов массивов в V8

Движок V8 (Chrome, Node.js) использует несколько внутренних представлений для массивов:

- **PACKED_SMI_ELEMENTS** — массив маленьких целых чисел (int31), плотный.
- **PACKED_DOUBLE_ELEMENTS** — массив чисел с плавающей точкой, плотный.
- **PACKED_ELEMENTS** — массив любых значений, плотный.
- **HOLEY_SMI_ELEMENTS** — разреженный массив целых чисел (с дырками).
- **HOLEY_ELEMENTS** — разреженный массив любых значений.
- **DICTIONARY_ELEMENTS** — массив, который выродился в хеш-таблицу (самый медленный режим).

Переход от PACKED к HOLEY происходит, когда в массиве появляются дырки. Переход к DICTIONARY_ELEMENTS происходит при
очень больших дырках или когда массив становится ассоциативным.

### Советы по оптимизации массивов в JS

1. **Не создавайте дырки.** Используйте `push()` вместо прямого присваивания по индексу, если только вы не заполняете
   массив последовательно с начала.

    ```javascript
    // Плохо — создаёт дырки
    const arr1 = [];
    arr1[100] = 42;  // первые 100 элементов — дырки
    
    // Хорошо — плотный массив
    const arr2 = [];
    arr2.push(42);   // понятный код, нет дырок
    
    // Или сразу задаём длину
    const arr3 = new Array(101);
    for (let i = 0; i < arr3.length; i++) {
        arr3[i] = i;   // Заполняем сплошь
    }
    ```

2. **Заполняйте массив одним типом элементов (если возможно).** V8 оптимизирует массивы, где все элементы одного типа.

    ```javascript
    // Хорошо — все числа
    const numbers = [1, 2, 3, 4, 5];  // PACKED_SMI_ELEMENTS
    
    // Плохо — смешанные типы
    const mixed = [1, "two", 3, "four"];  // PACKED_ELEMENTS (медленнее)
    ```

3. **Избегайте ассоциативного использования массивов.** Объекты предназначены для ключей-строк, массивы — для числовых
   индексов.

    ```javascript
    // Плохо — массив с нечисловым ключом
    const arr = [1, 2, 3];
    arr["key"] = "value"; 
    
    // Хорошо — объект для ключей-строк
    const obj = {0: 1, 1: 2, 2: 3, key: "value"};
    ```

4. **Задавайте начальную длину, если знаете её заранее.** Это позволяет V8 сразу выделить буфер нужного размера без
   лишних расширений.

    ```javascript
    // Хорошо — известна длина
    const n = 1000000;
    const arr = new Array(n);
    for (let i = 0; i < n; i++) {
        arr[i] = i;
    }
    
    // Плохо — неизвестна длина (частые расширения)
    const arr2 = [];
    for (let i = 0; i < n; i++) {
        arr2.push(i);  // Может происходить несколько расширений
    }
    ```

## Алгоритмическая сложность

### Что такое сложность?

Сложность алгоритма — это оценка того, как время выполнения (или потребление памяти) растёт с увеличением размера
входных данных. Это позволяет сравнивать алгоритмы и структуры данных независимо от скорости конкретного компьютера.

### O-нотация (О большое)

O-нотация описывает верхнюю границу роста. Она показывает, как быстро растёт время выполнения в худшем случае при
увеличении размера входных данных n.

### Основные классы сложности

#### O(1) — константная сложность

Время выполнения не зависит от размера данных. Это идеальный случай.

Примеры:

- Доступ к элементу массива по индексу (`arr[i]`)
- Вставка в конец массива (если есть место)
- Получение длины массива

```javascript
function getFirstElement(arr) {
    return arr[0];  // O(1) — выполняется за одинаковое время для любого размера
}
```

#### O(n) — линейная сложность

Время выполнения прямо пропорционально размеру входных данных.

Примеры:

- Поиск элемента в неотсортированном массиве
- Обход массива (суммирование, поиск максимума)
- Вставка/удаление в начало массива (сдвиг элементов)

```javascript
function findMax(arr) {
    let max = arr[0];
    for (let i = 1; i < arr.length; i++) {  // O(n) — цикл по всем элементам
        if (arr[i] > max) max = arr[i];
    }
    return max;
}
```

#### O(n²) — квадратичная сложность

Время выполнения пропорционально квадрату размера данных. Часто возникает при вложенных циклах.

Примеры:

- Пузырьковая сортировка (худший случай)
- Поиск дубликатов в массиве двойным циклом

```javascript
function findDuplicates(arr) {
    const duplicates = [];
    for (let i = 0; i < arr.length; i++) {        // O(n)
        for (let j = i + 1; j < arr.length; j++) {  // O(n) внутри
            if (arr[i] === arr[j]) duplicates.push(arr[i]);
        }
    }
    return duplicates;  // O(n²)
}

// Для 1000 элементов: до 500 000 итераций
// Для 10 000 элементов: до 50 000 000 итераций
```

#### O(n^x) — полиномиальная сложность

Общее название для всех степенных зависимостей (n³, n⁴ и т.д.). Почти всегда неприемлемо для больших данных.

#### O(log n) — логарифмическая сложность

Время выполнения растёт логарифмически. При увеличении данных в 1000 раз время выполнения растёт не в 1000 раз, а всего
в ~10 раз (log₂1000 ≈ 10). Это очень хорошая сложность.

Примеры:

- Поиск в отсортированном массиве (бинарный поиск)
- Операции в сбалансированных деревьях

```javascript
function binarySearch(arr, target) {
    let left = 0;
    let right = arr.length - 1;

    while (left <= right) {             // O(log n)
        const mid = Math.floor((left + right) / 2);
        if (arr[mid] === target) return mid;
        if (arr[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}

// Для 1 000 000 элементов: всего ~20 итераций
```

#### O(n log n) — линейно-логарифмическая сложность

Типичная сложность эффективных алгоритмов сортировки (QuickSort, MergeSort, TimSort).

Примеры:

- Быстрая сортировка (средний случай)
- Сортировка слиянием

```javascript
// Встроенная сортировка в JS — O(n log n) в среднем
const sorted = arr.sort((a, b) => a - b);
```

#### O(n!) — факториальная сложность

Самая плохая из распространённых сложностей. При n=20 уже невозможно выполнить за разумное время.

Примеры:

- Решение задачи коммивояжёра полным перебором
- Генерация всех перестановок массива

```javascript
// Генерация всех перестановок (3! = 6 перестановок)
// Для 10 элементов это уже 3 628 800 перестановок
// Для 20 элементов — 2 432 902 008 176 640 000 перестановок
```

### Визуальное сравнение сложностей

Для n = 1 000:

| Сложность  | Примерное количество операций | Значение          |
|------------|-------------------------------|-------------------|
| O(1)       | 1                             | Мгновенно         |
| O(log n)   | ~10                           | Мгновенно         |
| O(n)       | 1 000                         | Мгновенно         |
| O(n log n) | ~10 000                       | Очень быстро      |
| O(n²)      | 1 000 000                     | Заметная задержка |
| O(2^n)     | 1e301                         | Невозможно        |
| O(n!)      | 4e2567                        | Невозможно        |

### Нюансы оценки сложности

1. **Сложность может отличаться для лучшего, среднего и худшего случая.** Например, быстрая сортировка: лучший/средний —
   O(n log n), худший — O(n²).

    ```javascript
    // Поиск в массиве — разная сложность в зависимости от данных
    function findElement(arr, target) {
        for (let i = 0; i < arr.length; i++) {
            if (arr[i] === target) return i;
        }
        return -1;
    }
    
    // Лучший случай: элемент первый — O(1)
    // Средний случай: элемент в середине — O(n/2) = O(n)
    // Худший случай: элемента нет — O(n)
    ```

2. **Амортизированная сложность** — средняя стоимость операции в серии операций. Например, вставка в динамический
   массив (вектор), когда выделение нового буфера происходит редко. Амортизированно — O(1), хотя единичная операция
   расширения — O(n).

    ```javascript
    // Динамический массив (аналог push в JS)
    class DynamicArray {
        constructor() {
            this.data = new Array(4);
            this.length = 0;
        }

        push(value) {
            if (this.length === this.data.length) {
                // Расширение: O(n), но происходит редко
                const newData = new Array(this.data.length * 2);
                
                for (let i = 0; i < this.length; i++) {
                    newData[i] = this.data[i];
                }

                this.data = newData;
            }

            this.data[this.length] = value;
            this.length++;
        }
    }
    
    // Амортизированная сложность push: O(1)
    ```

3. **Константы имеют значение.** Алгоритм с O(n²) может быть быстрее алгоритма с O(n log n) для маленьких n из-за
   меньших констант.

4. **Сложность по памяти** — оценка дополнительной памяти, которую требует алгоритм. Например, сортировка слиянием
   требует O(n) дополнительной памяти.

## Выделение памяти под массив и максимальное количество элементов в JS

В JavaScript максимальная длина обычного массива ограничена 2³² - 1 (4 294 967 295) элементов, так как длина хранится в 32-битном беззнаковом целом.

Важный нюанс: создание массива через new Array(length) или Array(length) не выделяет физическую память под элементы. Оно только регистрирует адресное пространство и резервирует "дырки" (empty slots). Память выделяется lazily — по мере реальной записи элементов.

```js
// Всё ок — создание большого массива не выделяет физическую память
const hugeArray = new Array(4294967295);
console.log(hugeArray.length); // 4294967295
console.log(hugeArray[1000000]); // undefined (дырка)
// Память не выделена, программа работает

// При реальной записи начнёт выделяться память
hugeArray[1000000] = 42; // Теперь физическая память выделяется под один элемент
```

### Типизированные массивы

С типизированными массивами ситуация иная. Они представляют собой непрерывную область памяти фиксированного размера, и при создании физическая память выделяется сразу.

Максимальный размер типизированного массива ограничен:

- На 32-битных системах: до 2³¹ - 1 элементов (или меньше из-за ограничений памяти)

- На 64-битных системах: может быть больше, до 2⁵³ - 1 теоретически, но на практике — сколько позволит оперативная память и ограничения конкретного движка.

```javascript
// Типизированный массив — память выделяется сразу
const typed = new Uint8Array(4294967295);
// RangeError: Invalid typed array length
// На большинстве систем такое не пройдёт — слишком большой непрерывный кусок

// Для очень больших массивов размер нужно уменьшить
const largeTyped = new Uint8Array(1000000000); // 1 ГБ — может работать на 64-бит системах
```

## Операции с массивами и их сложность

| Операция                                     | Сложность  | Пояснение                             |
|----------------------------------------------|------------|---------------------------------------|
| Доступ по индексу `arr[i]`                   | O(1)       | Прямая формула адреса                 |
| Присваивание по индексу `arr[i] = x`         | O(1)       | То же самое                           |
| Получение длины `arr.length`                 | O(1)       | Длина хранится отдельно               |
| Добавление в конец `push()` (без расширения) | O(1)       | Просто запись в конец                 |
| Добавление в конец `push()` (с расширением)  | O(n)       | Выделение нового буфера + копирование |
| Удаление с конца `pop()`                     | O(1)       | Просто уменьшение счётчика            |
| Добавление в начало `unshift()`              | O(n)       | Сдвиг всех элементов вправо           |
| Удаление из начала `shift()`                 | O(n)       | Сдвиг всех элементов влево            |
| Вставка/удаление в середину `splice()`       | O(n)       | Сдвиг элементов                       |
| Поиск элемента `indexOf()`                   | O(n)       | Линейный проход в худшем случае       |
| Обход всех элементов `forEach()`             | O(n)       | Касаемся каждого элемента             |
| Сортировка `sort()`                          | O(n log n) | В среднем                             |
| Поиск в отсортированном массиве (бинарный)   | O(log n)   | Но только если массив отсортирован    |
| `map`, `filter`                              | O(n)       | Касаемся каждого элемента             |
| `reverse`                                    | O(n)       | Инвертирование порядка                |

## Подведение итогов

### Ключевые выводы

1. **Массивы — фундаментальная структура данных**, потому что они отражают устройство физической памяти. Понимание
   массивов необходимо для понимания производительности.

2. **Константный доступ по индексу O(1)** — главное преимущество массивов. Он достигается за счёт непрерывного хранения
   и формулы `базовый_адрес + индекс × размер_элемента`.

3. **Последовательный обход массива эффективен из-за работы кэш-памяти.** Процессор подгружает целые кэш-линии (64
   байта), поэтому соседние элементы в кэше.

4. **Выход за границы массива** — в безопасных языках (JS) обрабатывается безопасно, в опасных (C/C++) — Undefined
   Behavior с непредсказуемыми последствиями.

5. **Массивы в JS — гибрид:** могут быть плотными или разреженными, расти динамически, но за это приходится платить (
   проверки границ, возможное вырождение в хеш-таблицу).

6. **Типизированные массивы** — быстрая и компактная альтернатива для числовых данных, настоящие массивы фиксированного
   размера.

7. **Понимание O-нотации** необходимо для выбора правильного алгоритма и структуры данных. Разница между O(n), O(n²) и
   O(log n) при больших n — это разница между мгновенным ответом и ожиданием в несколько часов.

8. **Нет идеальной структуры данных** — массивы отличны для произвольного доступа и обхода, но плохи для
   вставки/удаления в середину или начало.

### Когда использовать массивы

**Массивы — лучший выбор, если:**

- Вам нужен произвольный доступ к элементам по индексу
- Основные операции — чтение и обход, а не вставка и удаление
- Размер данных фиксирован или известен заранее
- Важна локальность данных и эффективное использование кэша
- Вы работаете с числовыми данными (лучше брать типизированные массивы)

**Массивы не подходят, если:**

- Частые вставки и удаления в начало или середину (лучше взять оптимизированную структуру)
- Размер данных непредсказуем и сильно меняется
- Нужна эффективная вставка и поиск по ключу (лучше взять оптимизированную структуру)

### Производительность в JS: практические советы

1. Используйте типизированные массивы для числовых расчётов
2. Избегайте разреженных массивов (не создавайте дырки)
3. Если знаете размер заранее — создавайте массив с длиной
4. Используйте `push/pop` вместо `unshift/shift`, если порядок не важен
5. Для частых вставок/удалений в начало рассмотрите использование оптимизированной структуры данных
6. Помните, что встроенные методы (`map`, `filter`, `reduce`) часто хорошо оптимизированы

```javascript
// Быстро
const arr = new Array(1000000);
for (let i = 0; i < arr.length; i++) arr[i] = i;

// Медленно (частые расширения)
const arr2 = [];
for (let i = 0; i < 1000000; i++) arr2.push(i);

// Очень медленно (частые сдвиги)
const arr3 = [];
for (let i = 0; i < 1000000; i++) arr3.unshift(i);
```
