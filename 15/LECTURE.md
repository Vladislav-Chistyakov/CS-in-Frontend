# AI конспект для лекции #15

## Что такое граф

**Граф** — это математическая структура, состоящая из двух типов объектов:

- **Вершины (узлы, nodes)** — точки или объекты.
- **Рёбра (edges, дуги)** — связи между вершинами.

Формально граф обозначается как `G = (V, E)`, где `V` — множество вершин, `E` — множество рёбер.

Графы бывают:

- **Ориентированные (directed)** — рёбра имеют направление (стрелки).
- **Неориентированные (undirected)** — связи двусторонние.
- **Взвешенные (weighted)** — каждому ребру присвоено число (вес, стоимость, расстояние).
- **Разреженные (sparse)** — рёбер мало относительно количества вершин.
- **Плотные (dense)** — рёбер близко к максимально возможному количеству.

## Графы в программировании

Графы повсеместно используются в программировании для моделирования связей:

- Социальные сети (пользователи — вершины, дружба — рёбра).
- Транспортные сети (города — вершины, дороги — рёбра с весами).
- Веб-страницы (страницы — вершины, ссылки — ориентированные рёбра).
- Системы рекомендаций (товары — вершины, покупки — связи).
- Компиляторы (зависимости между модулями).
- Пакетные менеджеры (зависимости пакетов).
- Маршрутизация в сетях (роутеры — вершины, соединения — рёбра).

## Визуализация графов

Графы удобно изображать схематически: вершины — кружками с названиями, рёбра — линиями или стрелками. Для визуализации в
коде используются библиотеки: D3.js, Cytoscape.js, vis.js, Graphviz (dot).

## Применение графов

Основные задачи, решаемые с помощью графов:

- **Поиск пути** (кратчайший маршрут, алгоритмы Дейкстры, A*).
- **Обход графа** (посещение всех вершин).
- **Топологическая сортировка** (порядок выполнения задач с зависимостями).
- **Поиск циклов** (обнаружение циклических зависимостей).
- **Кластеризация и сообщества** (группировка связанных вершин).
- **Ранжирование** (PageRank).

## Способы представления графа в памяти

Выбор способа хранения графа влияет на эффективность операций (проверка наличия ребра, перебор соседей, добавление
удаление) и потребление памяти.

### Матрица смежности (adjacency matrix)

Двумерная матрица `|V| × |V|`, где элемент `[i][j]` равен:

- `1` (или вес) если есть ребро из `i` в `j`;
- `0` если ребра нет.

Для неориентированного графа матрица симметрична относительно главной диагонали.

**Пример:**

Вершины: A, B, C. Рёбра: A→B, B→C, C→A.

```text
A B C
A   0 1 0
B   0 0 1
C   1 0 0
```

**Сложность:**

| Операция                     | Время |
|------------------------------|-------|
| Проверка наличия ребра       | O(1)  |
| Перебор всех соседей вершины | O(V)  |
| Добавление/удаление ребра    | O(1)  |

**Память:** O(V²).

**Плюсы:** быстрый доступ, простота реализации.

**Минусы:** занимает много памяти (O(V²)) — не подходит для разреженных графов.

**Когда использовать:** плотные графы, частые проверки наличия рёбер.

### Матрица инцидентности (incidence matrix)

Двумерная матрица `|V| × |E|`, где элемент `[v][e]` показывает, участвует ли вершина `v` в ребре `e`.

Для ориентированных графов:

- `1` — вершина — начало ребра;
- `-1` — вершина — конец ребра;
- `0` — вершина не участвует.

Для неориентированных:

- `1` — вершина инцидентна ребру;
- `0` — не инцидентна.

**Пример (ориентированный граф):**

Вершины: A, B, C. Рёбра: e1: A→B, e2: B→C, e3: C→A.

```text
e1 e2 e3
A    1  0 -1
B   -1  1  0
C    0 -1  1
```

**Память:** O(V × E).

**Минусы:** большие затраты памяти при разреженных графах, менее интуитивно.

**Когда использовать:** редко, в основном в теоретических задачах.

### Список рёбер (edge list)

Простой массив или список всех рёбер. Каждое ребро хранится как кортеж `(from, to, weight)`.

**Пример:**

```javascript
const edges = [
    {from: "A", to: "B", weight: 5},
    {from: "B", to: "C", weight: 3},
    {from: "A", to: "C", weight: 2}
];
```

**Сложность:**

| Операция                     | Время                           |
|------------------------------|---------------------------------|
| Проверка наличия ребра       | O(E) — нужно пройти весь список |
| Перебор всех соседей вершины | O(E)                            |
| Добавление ребра             | O(1)                            |

**Память:** O(E).

**Плюсы:** экономично для памяти, простота, удобно для операций, проходящих по всем рёбрам (например, построение
минимального остова).

**Минусы:** медленный поиск рёбер и соседей.

**Когда использовать:** когда основная операция — итерация по всем рёбрам (алгоритмы Краскала, Прима).

### Структура смежности (adjacency list)

Самый популярный способ для большинства задач. Для каждой вершины хранится список (массив, связный список, хеш-таблица)
её соседей.

**Пример:**

```javascript
const graph = {
    A: [{node: "B", weight: 5}, {node: "C", weight: 2}],
    B: [{node: "C", weight: 3}],
    C: []
};
```

**Сложность:**

| Операция                     | Время                          |
|------------------------------|--------------------------------|
| Проверка наличия ребра       | O(deg(v)) — до степени вершины |
| Перебор всех соседей вершины | O(deg(v))                      |
| Добавление ребра             | O(1) (в конец списка)          |

**Память:** O(V + E) для ориентированных, O(V + 2E) для неориентированных.

**Плюсы:** эффективно для разреженных графов, быстрый перебор соседей.

**Минусы:** медленная проверка существования ребра (но можно ускорить, используя хеш-таблицы вместо массивов).

**Когда использовать:** практически везде — обходы (DFS, BFS), поиск путей, большинство алгоритмов на графах.

## Частные случаи графов

### Связанный список — частный случай графа

Связный список — это **ориентированный граф**, у которого:

- каждая вершина имеет не более одного исходящего ребра;
- последовательность вершин выстроена в цепочку;
- возможен цикл (кольцевой список).

```text
A → B → C → D
```

### Дерево — частный случай графа

Дерево — это **связный ациклический неориентированный граф**. Свойства дерева:

- ровно `V-1` ребро;
- между любыми двумя вершинами существует единственный путь;
- удаление любого ребра разрывает связность.

Частные случаи деревьев: бинарное дерево, дерево поиска, куча.

## Базовые понятия графов

- **Степень вершины (degree)** — количество инцидентных ей рёбер. Для ориентированных: **входная степень (indegree)** и
  **выходная степень (outdegree)**.
- **Путь (path)** — последовательность вершин, где каждая следующая соединена с предыдущей ребром.
- **Цикл (cycle)** — путь, у которого первая и последняя вершины совпадают.
- **Связный граф (connected graph)** — между любыми двумя вершинами существует путь.
- **Компонента связности** — максимальное подмножество вершин, в котором граф связен.
- **Ациклический граф (DAG — Directed Acyclic Graph)** — ориентированный граф без циклов.

## Пакетные менеджеры и циклы в зависимостях

Пакетные менеджеры (npm, yarn, pip, cargo) строят граф зависимостей пакетов. **Цикл в зависимостях** — ошибка, при
которой пакет A зависит от B, B зависит от C, а C зависит от A. Это делает невозможным установку пакетов в правильном
порядке.

Обнаружение циклов — стандартная задача при разрешении зависимостей.

## Применение графов

Кроме перечисленных выше, графы используются в:

- **Системах контроля версий** (Git — граф коммитов).
- **Базах данных** (графовые БД, оптимизация запросов через планы выполнения — деревья).
- **Компиляторах** (граф вызовов, граф потоков данных).
- **Рекомендательных системах** (коллаборативная фильтрация через графы).
- **Анализе кода** (построение графа зависимостей между модулями).

## Транзитивное замыкание (transitive closure)

**Транзитивное замыкание** графа — это новый граф, в котором ребро `(u, v)` существует, если в исходном графе есть
путь (любой длины, включая ноль шагов) из `u` в `v`.

Простыми словами: если из A можно добраться до B через другие вершины, в транзитивном замыкании появляется прямое ребро
A→B.

**Как строится:** обычно с помощью алгоритма Флойда–Уоршелла (O(V³)) или многократного DFS/BFS (O(V × (V+E))).

**Применение:**

- анализ достижимости в графах;
- оптимизация запросов к графовым базам данных;
- вычисление замыкания по зависимостям.

## Графовые базы данных (Neo4j, ArangoDB)

Графовые базы данных хранят данные как вершины и рёбра, оптимизируя операции обхода.

- **Neo4j** — самая популярная. Использует язык запросов Cypher.
- **ArangoDB** — мультимодельная (документы + графы).
- **TigerGraph, JanusGraph, Dgraph** — другие представители.

**Когда нужны графовые БД:** когда важны связи между данными (соцсети, системы рекомендаций, fraud detection, управление
зависимостями).

```cypher
// Пример запроса в Neo4j: друзья друзей
MATCH (user:User {name: "Alice"})-[:FRIEND_OF*2]->(friend)
RETURN friend.name
```

**Сравнение с реляционными БД:** в реляционных связь через JOIN-ы становится дорогой при большой глубине. Графовые БД
хранят рёбра как физические ссылки, что делает обходы быстрыми независимо от глубины.

## Обход графа (посещение всех вершин)

Обход графа — это алгоритм, который посещает каждую вершину графа (или проходит по всем рёбрам) в определённом порядке.
Два основных типа:

### Поиск в глубину (DFS — Depth-First Search)

Идём «вглубь»: от текущей вершины переходим к первому непосещённому соседу, затем от него — дальше. Если дальше идти
некуда — возвращаемся (бэктрекинг).

**Реализация (рекурсивная):**

```javascript
function dfs(graph, vertex, visited = new Set()) {
    visited.add(vertex);
    console.log(vertex);

    for (const neighbor of graph[vertex]) {
        if (!visited.has(neighbor)) {
            dfs(graph, neighbor, visited);
        }
    }
}
```

**Реализация (итеративная с явным стеком):**

```javascript
function dfsIterative(graph, start) {
    const visited = new Set();
    const stack = [start];

    while (stack.length > 0) {
        const vertex = stack.pop();
        if (visited.has(vertex)) continue;
        visited.add(vertex);
        console.log(vertex);

        for (const neighbor of graph[vertex]) {
            if (!visited.has(neighbor)) {
                stack.push(neighbor);
            }
        }
    }
}
```

**Сложность:** O(V + E) при использовании списка смежности.

### Поиск в ширину (BFS — Breadth-First Search)

Идём «вширь»: сначала посещаем всех соседей текущей вершины, затем соседей соседей и так далее. Используется очередь (
FIFO).

```javascript
function bfs(graph, start) {
    const visited = new Set();
    const queue = [start];

    while (queue.length > 0) {
        const vertex = queue.shift();
        if (visited.has(vertex)) continue;
        visited.add(vertex);
        console.log(vertex);

        for (const neighbor of graph[vertex]) {
            if (!visited.has(neighbor)) {
                queue.push(neighbor);
            }
        }
    }
}
```

**Сложность:** O(V + E).

## Сравнение DFS и BFS: стек → глубина, очередь → ширина

| Аспект                  | DFS                       | BFS                       |
|-------------------------|---------------------------|---------------------------|
| Структура данных        | Стек (явный или рекурсия) | Очередь                   |
| Порядок обхода          | Вглубь по одному пути     | По слоям (вширь)          |
| Память в худшем случае  | O(V) — при глубоком графе | O(V) — при широком графе  |
| Находит кратчайший путь | Нет (обходит всех)        | Да (в невзвешенном графе) |
| Использует рекурсию     | Естественно               | Нет                       |

**Когда что использовать:**

- **DFS** — проверка существования пути, топологическая сортировка, поиск компонент связности, обход в глубину дерева.
- **BFS** — поиск кратчайшего пути в невзвешенном графе, проверка двудольности, обход по слоям.

## Топологическая сортировка (topological sort)

**Топологическая сортировка** — это упорядочивание вершин ориентированного ациклического графа (DAG), при котором для
каждого ребра `(u, v)` вершина `u` идёт раньше `v`.

Простыми словами: если задача A должна быть выполнена до задачи B, то A будет раньше B в топологическом порядке.

**Алгоритм (на основе DFS):**

```javascript
function topologicalSort(graph) {
    const visited = new Set();
    const stack = [];

    function dfs(vertex) {
        visited.add(vertex);
        for (const neighbor of graph[vertex]) {
            if (!visited.has(neighbor)) {
                dfs(neighbor);
            }
        }
        stack.push(vertex); // добавляем после обработки всех потомков
    }

    for (const vertex in graph) {
        if (!visited.has(vertex)) {
            dfs(vertex);
        }
    }

    return stack.reverse(); // в обратном порядке
}
```

**Алгоритм Кана (на основе подсчёта входящих степеней):**

```javascript
function topologicalSortKahn(graph) {
    const indegree = {};
    const queue = [];
    const result = [];

    // Подсчёт входящих степеней
    for (const u in graph) {
        indegree[u] = indegree[u] || 0;
        for (const v of graph[u]) {
            indegree[v] = (indegree[v] || 0) + 1;
        }
    }

    // Находим вершины с нулевой входящей степенью
    for (const v in indegree) {
        if (indegree[v] === 0) queue.push(v);
    }

    while (queue.length > 0) {
        const u = queue.shift();
        result.push(u);

        for (const v of graph[u]) {
            indegree[v]--;
            if (indegree[v] === 0) queue.push(v);
        }
    }

    if (result.length !== Object.keys(graph).length) {
        throw new Error("Граф содержит цикл");
    }
    return result;
}
```

**Сложность:** O(V + E).

## Пример: «Как стать инженером»

Граф зависимостей навыков:

```text
Математика → Алгоритмы → Программирование
Физика → Математика
Программирование → Архитектура ПО
Архитектура ПО → Инженер
Алгоритмы → Инженер
```

Топологическая сортировка даст порядок изучения:

`Физика → Математика → Алгоритмы → Программирование → Архитектура ПО → Инженер`

## Итоги лекции

- **Граф** — структура из вершин и рёбер, моделирующая связи.
- **Способы представления графа** в памяти:
  - Матрица смежности — быстрый доступ, но O(V²) памяти.
  - Матрица инцидентности — редко используется.
  - Список рёбер — экономично, но медленный поиск.
  - Список смежности — оптимальный выбор для большинства задач.
- **Связанный список** и **дерево** — частные случаи графов.
- **Обходы графа**:
  - DFS (глубина, стек) — рекурсивный или итеративный с явным стеком.
  - BFS (ширина, очередь) — поиск кратчайшего пути в невзвешенном графе.
- **Топологическая сортировка** — порядок вершин DAG, учитывающий зависимости (алгоритмы: на основе DFS или Кана).
- **Графовые базы данных** (Neo4j и др.) эффективны для данных с сильными связями.
- **Циклы в зависимостях** — ошибка, обнаруживаемая топологической сортировкой.
